# RepoWiki 使用教程

> 适用版本：2026-06-10 | 阅读时间：20 分钟

## 一、这是什么

RepoWiki 是一个 **AI 驱动的公司知识库**。你把公司的文档、代码、规范导入后，它会：

- **自动阅读理解** — 每份文档/代码文件提取摘要、关键词、关键事实
- **自动分类代码** — 按技术层级（handler/service/model）和业务域（订单/配送/门店）归类
- **自动整理知识** — 识别文档中提到的实体和概念，跨文档累积
- **智能问答** — 用自然语言提问，AI 结合知识库内容回答
- **质量检测** — 自动检查空壳页面、AI 幻觉产物、过期文档

简单说：**把散落各处的文档变成可搜索、可问答的结构化知识库。**

## 二、快速开始

### 2.1 启动服务

联系管理员获取：
- 服务地址（如 `http://10.0.1.50:8080`）
- DeepSeek API Key（如需自己启动）

自己安装：

```bash
# Mac：解压安装包后双击 start.command
# Windows：解压后双击 start.bat
# 首次运行会提示输入 DeepSeek API Key

# 或从源码启动：
cd repowiki
go build -o repowiki ./cmd/... && ./repowiki
```

### 2.2 打开界面

浏览器访问 `http://localhost:8080`。

## 三、配合 CodeBuddy 导入公司项目（推荐方式）

对于大型项目（几十到几百个文件），推荐用 CodeBuddy AI 助手完成导入，比手动在 Web UI 操作更高效。

### 3.1 前置准备

确保 CodeBuddy 已安装项目专用 Skill（团队内一次执行即可）：

```bash
bash /path/to/repowiki/skills/install.sh
```

这会把 5 个 Skill 安装到 `~/.codebuddy/skills/user/`：
- `wiki-import-auditor` — 分析项目结构，筛选应导入的文件
- `wiki-sync-guardian` — 导入前检查是否重复、路径是否正确
- `wiki-quality-detector` — 深度质量检测
- `wiki-deduplicator` — 跨项目去重
- `wiki-query-refiner` — 模糊问题多维度扩展

### 3.2 导入新项目（标准流程）

在 CodeBuddy 对话框中发送：

> 帮我把 `/path/to/new-project` 导入到知识库，项目名是「新项目」，子项目名是「new-service」

CodeBuddy 会自动按以下流程执行：

```
第一步：wiki-import-auditor 自动激活
  → 扫描项目目录结构
  → 识别技术栈和框架
  → 输出 T1-T4 四层筛选方案
  → T1: 必须导入（controller/service/model/route/入口）
  → T2: 建议导入（组件/SDK/配置/文档）
  → T3: 按需导入（工具/测试/SQL）
  → T4: 跳过（node_modules/dist/build/生成文件）
  → 你确认方案后进入下一步

第二步：wiki-sync-guardian 自动激活
  → 检查是否已有重复导入
  → 检查跨项目文件碰撞
  → 检查路径合理性
  → 全部通过后执行导入

第三步：POST /api/ingest 执行导入
  → 文件归档 + 哈希记录
  → 代码文件：自动分类（层级 + 业务域 + 类型）
  → 文档文件：LLM 提取摘要 + 实体/概念
  → 跳过测试/mock/生成/样式文件
  → 导入完成后自动生成「代码模块索引」页

第四步（可选）：wiki-quality-detector 质检
  → 导入完成后做一次深度质检
  → 检查是否有 LLM 幻觉产物
  → 检查空壳页面
```

### 3.3 导入已有项目的更新

项目代码更新后，对同一个目录再次执行导入即可。系统自动：

- 哈希对比 → 只处理变化的文件
- 已删除的实体/概念不删除（只新增不删除）
- 相关综合页标记为 stale（提醒重新提炼）
- 重新生成「代码模块索引」

### 3.4 直接用 API 导入（不用 CodeBuddy）

**先做前置检查：**
```bash
curl -X POST http://localhost:8080/api/ingest/validate \
  -H "Content-Type: application/json" \
  -d '{"raw_path":"/path/to/project","project":"我的项目","sub_project":"my-service"}'
```

**确认无误后执行导入：**
```bash
curl -X POST http://localhost:8080/api/ingest \
  -H "Content-Type: application/json" \
  -d '{"raw_path":"/path/to/project","project":"我的项目","sub_project":"my-service"}'
```

响应中会带 `validation` 字段显示校验结果。

**或在 Web UI 操作：**
1. 点击左侧「导入文档」
2. 选择目标项目和子项目
3. 输入文件夹路径
4. 点击「开始导入」

## 四、主要功能

### 4.1 浏览代码模块索引

导入代码后，系统自动按业务域和技术层级生成聚合页。

1. 点击左侧「浏览 Wiki」
2. 选择「综合提炼」分类
3. 找到「代码模块索引」

你会看到：

```
## 按业务域浏览

### 订单
**API入口**
- SendOrderHandler — POST /api/order/send
**业务逻辑**
- SendOrderLogic — 发单核心流程
**数据模型**
- OrderModel — 订单表结构

### 配送
...
```

点击任意链接即可跳转到对应代码的 AI 摘要页。

### 4.2 智能问答

1. 点击左侧「智能问答」
2. 选择项目（和可选的子项目）
3. 输入问题，如"订单状态有哪些？"、"SendOrder 接口需要哪些参数？"

**提问技巧：**

| 好的提问 | 不好的提问 |
|---|---|
| "SendOrder 接口需要哪些参数？" | "订单" |
| "第三方平台的回调地址怎么配置？" | "配送怎么搞" |
| "my-service 中手动添加订单的流程" | "那个添加功能" |

**项目范围选择：**
- 问具体子项目的代码实现 → 指定 sub_project（最快、最准）
- 问跨模块的业务流程 → 只指定 project（聚合所有子项目）
- 问公司规范 → 选「通用」项目

### 4.3 浏览 Wiki

1. 点击左侧「浏览 Wiki」
2. 五个分类：
   - **源文档摘要** — 文档/代码的 AI 摘要（代码页含 layer/domain/kind 标签）
   - **实体索引** — 具体事物（人、系统、项目）
   - **概念索引** — 抽象术语（技术方法、设计模式）
   - **综合提炼** — 跨文档分析 + **代码模块索引**
   - **矛盾记录** — 文档间信息冲突

### 4.4 综合提炼

选一个主题，AI 跨所有相关文档做综合分析。

1. 点击「综合提炼」
2. 输入主题词
3. 点击「开始提炼」

输出：综合摘要 + 关键洞察 + 矛盾点 + 知识空白。

### 4.5 质量检查

1. 点击「质量检测」
2. 系统自动扫描

| 严重度 | 含义 | 建议 |
|---|---|---|
| error | 单字符名（AI 幻觉）、无实质内容 | 删除 |
| warning | 内容过少、仅含占位符 | 检查后处理 |
| info | 草稿、源文档有新版未同步 | 审核 |

### 4.6 统计面板

查看知识库整体数据：各项目页面数、质量统计、子项目分布。

## 五、导入时自动做了什么

了解这些有助于理解系统行为：

| 自动操作 | 说明 |
|---|---|
| **跳过噪声文件** | 测试（`*_test.go`）、生成代码（`*.pb.go`）、mock、样式、构建产物 |
| **代码自动分类** | 每个代码文件按路径规则打 layer/domain/kind 标签 |
| **增量更新** | SHA256 哈希对比，不变的文件直接跳过 |
| **实体/概念跳过** | SOP/标准/规范/PRD 类文档不拆实体概念，代码文件也不拆 |
| **模块聚合页** | 导入完成后自动生成「代码模块索引」 |
| **历史快照** | 更新时旧版存 `wiki/history/` |

## 六、常见问题

**Q: 导入后搜不到内容？**
A: 等导入完成（控制台出现 `[完成]`），再刷新页面。

**Q: 问答不准？**
A: 指定子项目缩小范围；问题用专有名词。

**Q: 看到很多「待补充」空页面？**
A: 用「质量检测」批量删除。SOP/规范类文档和代码文件已自动跳过实体提取。

**Q: 文档更新了怎么同步？**
A: 对同目录再执行一次导入，自动检测变化。

**Q: 新项目怎么导入最省事？**
A: 用 CodeBuddy（见第三章），自动分析项目结构 → 筛选文件 → 前置检查 → 执行导入，全程不用手动操作。

## 七、API 接口速查

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/ingest` | 导入文档 |
| POST | `/api/ingest/validate` | 导入前置检查（只读） |
| POST | `/api/query` | 智能问答 |
| POST | `/api/synthesize` | 综合提炼 |
| GET | `/api/stats` | 知识库统计 |
| GET | `/api/lint` | 质量检查 |
| GET | `/api/wiki/list/{category}` | 列出页面 |
| GET | `/api/wiki/page/{cat}/{name}` | 读取页面 |
| DELETE | `/api/wiki/page/{cat}/{name}` | 删除页面 |
| POST | `/api/projects` | 创建项目 |
| GET | `/api/projects` | 列出项目 |
| GET | `/api/project/{name}` | 项目详情 |

所有接口支持 `?project=xxx&sub_project=xxx` 参数做项目/子项目隔离。
