# 本地运行 → 公司级部署 转换方案

> 当前状态：单机 localhost 运行 | 目标：公司内多人可用 | 支持 Mac + Windows

## 零、用户安装指南（给公司员工看）

### Mac 用户

1. 从 GitLab Release 页面下载 `repowiki-{版本}-darwin-arm64.tar.gz`（Apple Silicon）或 `darwin-amd64`（Intel）
2. 双击解压，得到 `repowiki-xxx/` 文件夹
3. 双击 `start.sh` → 首次运行会提示输入 DeepSeek API Key
4. 浏览器自动打开 `http://localhost:8080`，开始使用

**如果 Mac 提示"无法验证开发者"：**
系统偏好设置 → 安全性与隐私 → 仍要打开

### Windows 用户

1. 从 GitLab Release 页面下载 `repowiki-{版本}-windows-amd64.zip`
2. 右键解压到任意目录
3. 双击 `start.bat` → 首次运行会提示输入 API Key
4. 浏览器自动打开 `http://localhost:8080`

**如果 Windows Defender 报警：** 点击"更多信息" → "仍要运行"

### 获取 API Key

联系管理员获取 DeepSeek API Key，或自行在 https://platform.deepseek.com 注册获取。

## 一、当前架构 vs 目标架构

```
【当前 — 单机本地】
  用户浏览器 ──→ localhost:8080 ──→ Go Binary ──→ 本地文件系统
                    │                    │
                    └─ DeepSeek API       └─ knowledge-base/（Markdown + .hash）

【目标 — 公司内部服务】
  员工A ─┐
  员工B ─┼─→ https://wiki.internal.com ──→ Nginx ──→ Go Service ──→ SQLite / 文件系统
  员工C ─┘         │                                    │
              [OAuth/SSO 登录]                    └─ DeepSeek API
```

## 二、分阶段迁移路径

### 第一阶段：最小可用（1-2 天）

让公司内其他员工能通过浏览器访问，不改变代码架构。

**需要做的事：**

1. **配置内网 IP 访问**
   ```bash
   # .env 中改为监听所有网卡
   PORT=8080
   # main.go 中改为 0.0.0.0:8080
   ```
   员工浏览器访问 `http://{服务器IP}:8080` 即可。

2. **最简鉴权（可选）**
   在 Nginx 层加 HTTP Basic Auth：
   ```nginx
   server {
       listen 80;
       server_name wiki.internal;
       
       auth_basic "Wiki";
       auth_basic_user_file /etc/nginx/.htpasswd;
       
       location / {
           proxy_pass http://127.0.0.1:8080;
       }
   }
   ```
   ```bash
   htpasswd -c /etc/nginx/.htpasswd admin  # 创建账号
   ```

3. **systemd 保活**
   ```ini
   # /etc/systemd/system/repowiki.service
   [Unit]
   Description=RepoWiki Service
   After=network.target
   
   [Service]
   Type=simple
   WorkingDirectory=/opt/repowiki
   ExecStart=/opt/repowiki/repowiki
   Restart=always
   RestartSec=5
   
   [Install]
   WantedBy=multi-user.target
   ```
   ```bash
   sudo systemctl enable --now repowiki
   ```

**这个阶段的限制：**
- 无并发写入保护（多人同时导入可能文件冲突）
- 前端无登录态感知
- 单机文件系统，无备份

### 第二阶段：生产可用（1-2 周）

解决并发、备份、运维问题。

**2.1 写入并发保护**

当前 ingest 操作没有文件级锁。改 `engine.go` 添加写锁：

```go
// engine.go 新增字段
type Engine struct {
    // ... 现有字段
    writeMu sync.Mutex  // 保护 ingest 和 delete 操作
}

// 在 IngestAll 和 DeletePage 开头加锁
func (e *Engine) IngestAll(...) {
    e.writeMu.Lock()
    defer e.writeMu.Unlock()
    // ...
}
```

或更细粒度：改为异步导入队列（channel + 单 worker），避免导入操作互相阻塞。

**2.2 数据库兜底（SQLite 可选方案）**

当源文档超过 ~1000 篇时，文件系统遍历可能变慢。可选方案是用 SQLite 做元数据索引：

```
knowledge-base/
├── wiki.db          ← SQLite（新增）：存所有页面的 title/summary/tags/frontmatter
├── raw/             ← 保持文件系统（原始文件太大不适合 SQLite）
└── wiki/            ← 保持文件系统（Markdown 正文）
```

好处：
- 依然是单文件部署（SQLite 是一个文件）
- 统计、搜索、列表查询从文件遍历变成 SQL 查询
- 可以加全文搜索（SQLite FTS5）

**不需要改**倒排索引（InMemorySearch）——它仍然是搜索的主力，SQLite 只替代文件遍历。

**2.3 日志和监控**

```bash
# systemd journal 自带日志
journalctl -u repowiki -f

# 加健康检查端点
# GET /api/health → {"status":"ok","uptime":"3d 2h"}
```

**2.4 定时备份**

```bash
# crontab: 每天凌晨 2 点备份 knowledge-base/
0 2 * * * cd /opt/repowiki && tar -czf backups/wiki-$(date +%Y%m%d).tar.gz knowledge-base/

# 或者直接 git
0 2 * * * cd /opt/repowiki/knowledge-base && git add -A && git commit -m "auto backup $(date +%Y%m%d)" && git push
```

---

### 第三阶段：团队规模扩展（可选，按需）

当使用人数 >10 人、知识库文档 >5000 篇时考虑。

**3.1 真正的用户认证**

替换 Nginx Basic Auth 为 OAuth2/SSO：
- 接入公司已有的 SSO 系统
- Go 服务加 JWT 中间件
- 前端加登录页面

**3.2 读写分离**

```
               ┌─ Go Service (主) ──── 写操作(ingest/delete)
Nginx ────────┤
               └─ Go Service (只读) × 2 ── 读操作(query/stats/browse)
```

主节点写入后通知只读节点重建索引。

**3.3 LLM 成本控制**

多人使用后 API 调用量会上去。控制策略：
- 问答结果缓存（同一问题 1 小时内复用）
- 导入频率限制（每人每天最多 3 次）
- LLM 调用预算告警

## 三、快速部署清单

| 步骤 | 命令 / 操作 | 耗时 |
|---|---|---|
| 1. 服务器准备 | Linux 机器（2C4G 起步），安装 Go 1.22+ | 30min |
| 2. 部署代码 | `git clone && go build` | 5min |
| 3. 配置 API Key | 创建 `.env` 文件 | 2min |
| 4. 配置 systemd | 复制 service 文件 | 5min |
| 5. Nginx 反向代理 | 复制 nginx 配置 | 10min |
| 6. 添加 Basic Auth | `htpasswd` 创建账号 | 2min |
| 7. 配置备份 | crontab + git | 5min |
| 8. 分发访问地址 | 告知员工 `http://{IP}` | — |

**总计：约 1 小时可完成基础部署。**

## 四、成本估算

| 项目 | 估算 |
|---|---|
| 服务器 | 2C4G 云服务器，~100 元/月 |
| DeepSeek API | deepseek-chat 模型，导入 100 篇文档约 0.5-2 元；日常问答每次约 0.01-0.05 元 |
| 存储 | 1000 篇文档 + wiki 页面，约 50-200MB |
| 带宽 | 内网访问，可忽略 |

**月度总成本预估：服务器 100 元 + API 50-200 元 ≈ 150-300 元/月**（取决于导入频率和问答量）

## 五、安全检查清单

部署前确认：

- [ ] `.env` 文件权限设为 600（`chmod 600 .env`）
- [ ] API Key 不提交到 git（`.env` 已在 `.gitignore` 中）
- [ ] Nginx 配置了 `auth_basic`
- [ ] 防火墙只开放 80/443 端口（不直接暴露 8080）
- [ ] Go 服务的路径穿越防护已就位（`safeWikiPagePath` 函数）
- [ ] 定期更新 DeepSeek API Key
- [ ] `knowledge-base/` 目录有定期备份
