# 需求文档：外卖订单主流程

| 项目 | 内容 |
| --- | --- |
| 需求名称 | 外卖订单下单-支付-配送主流程 |
| 版本 | v1.2 |
| 状态 | 已评审 |
| 负责人 | 交易组 |

## 1. 背景与目标

当前门店的点单入口分散在小程序与收银台两套系统中，订单数据不互通，导致：

- 顾客在收银台下单后无法在 App 中查看配送进度；
- 支付成功但订单状态未同步时，需要人工在后台补单，日均 30+ 单；
- 退款需要财务手工操作，时效约 24 小时。

**目标**：统一订单中心承载全部渠道订单，实现「下单 → 支付 → 配送 → 完成/退款」全链路状态自动流转，把人工补单降到 0，退款时效压缩到 10 分钟内。

## 2. 范围

**本期包含**

- 订单创建、查询、取消
- 微信 / 支付宝 / 余额三种支付渠道
- 运力呼叫与配送状态回传
- 支付与配送回调的幂等处理

**本期不包含**

- 优惠券与满减（下期，放在营销中心）
- 预约单与定时配送
- 跨店合并下单

## 3. 角色

| 角色 | 关注点 |
| --- | --- |
| 顾客 | 下单是否成功、配送要多久、能不能退 |
| 门店店员 | 有没有新单、能不能看到备注 |
| 骑手 | 取货地址、送达确认 |
| 财务 | 退款是否到账、日终对账平不平 |

## 4. 主流程

### 4.1 下单

1. 顾客在门店页选择商品，提交订单；
2. 系统校验：门店是否存在且营业中、商品是否在售、数量与单价是否合法；
3. 校验通过后生成订单号（`ORD` + 日期 + 6 位序列），状态 `created`；
4. 金额计算：`订单总额 = Σ(单价 × 数量) + 配送费`，金额一律以分为单位存储，避免浮点误差。

**异常**：门店打烊、商品下架 → 提示用户并阻断下单；重复提交（同一用户 3 秒内相同商品）→ 复用首单，不重复创建。

### 4.2 支付

1. 顾客选择渠道发起支付，系统创建支付单并向渠道换取预支付参数；
2. 用户在渠道侧完成付款，渠道异步回调支付结果；
3. 系统验签通过后：先结算支付单，再推进订单状态为 `paid`；
4. 支付单结算与订单推进**不在同一事务**——钱已到账不能因订单状态推进失败而回滚，失败由补偿任务重试。

**幂等要求**：渠道可能多次投递同一条回调，同一 `payment_id` 重复回调必须只入账一次。

**超时**：订单创建后 15 分钟未支付自动取消，释放库存。

### 4.3 配送

1. 订单支付成功后，系统向运力平台呼叫骑手，拿到配送单号，订单状态推进为 `delivering`；
2. 骑手接单、到店、送达等节点由运力平台回调同步；
3. 收到「已送达」后订单状态推进为 `completed`；
4. 配送中间态（接单、配送中）不改变订单状态，仅记录骑手信息供前端展示。

**异常**：运力呼叫失败 → 订单停留在 `paid`，进入重试队列，每 30 秒重试一次，最多 10 次后转人工。

### 4.4 取消与退款

- `created` 状态：用户可直接取消，订单置为 `canceled`，无需退款；
- `paid` 及以后：必须先发起退款，退款成功后订单置为 `refunded`；
- 退款为**原路退回**，到账时间以渠道为准（微信 1-3 个工作日，支付宝实时，余额实时）。

## 5. 状态机

```
created ──支付成功──> paid ──呼叫运力──> delivering ──送达──> completed
   │                    │
   │ 取消                │ 退款
   v                    v
canceled             refunded
```

合法流转穷举（其余组合一律拒绝）：

| 起始 | 允许流转到 |
| --- | --- |
| created | paid, canceled |
| paid | delivering, refunded |
| delivering | completed, refunded |
| completed | — （终态） |
| canceled | — （终态） |
| refunded | — （终态） |

## 6. 非功能需求

| 项 | 要求 |
| --- | --- |
| 下单接口 P99 | < 300ms |
| 支付回调处理 | 收到后 2 秒内应答，避免渠道判定超时重投 |
| 数据一致性 | 订单与支付单最终一致，允许秒级延迟 |
| 日志 | 每次状态流转记录 `order_id`、原状态、新状态、触发方 |
| 对账 | 每日 02:00 拉取渠道账单，差异单生成告警工单 |

## 7. 埋点与监控

- 下单成功率、支付成功率、配送超时率三个核心指标接入看板；
- 支付回调验签失败率 > 1% 触发告警（可能是密钥配置错误或恶意请求）；
- 待人工介入的订单（配送取消、运力呼叫失败超限）进入值班工单。

## 8. 开放问题

1. 部分退款（只退其中一件商品）是否本期支持？——倾向下期，需财务确认。
2. 骑手送达确认与用户确认收货冲突时以谁为准？——暂以骑手为准，保留用户申诉入口。
